# 水下载具三维立体导航演示

在沉船外壳、洞穴与悬垂结构之间为**有尺寸的水下运载器**搜索真正的三维路径。
路径不是“水平地图 + 高度标注”，而是在体素配置空间中用 26 邻接 A* 同时搜索
向上、向下与斜向运动；窄缝可通过性按**整个载具盒体**判定，并对平滑后的路线
做连续扫掠碰撞复核。

## 界面怎样启动

前置条件：Node.js 18+（已在 Node 22 上验证），依赖仅 `three`，已随包安装。

```bash
cd underwater-nav
npm install        # 仅首次，安装本地 three.js
npm start          # 等价于 node server.js
```

控制台出现 `Underwater navigation demo: http://localhost:8080` 后，浏览器打开
<http://localhost:8080>。端口可用 `PORT=9000 npm start` 修改。

界面操作顺序：

1. 左侧选择场景（沉船 / 斜向狭孔 / 封闭空腔）。
2. 调整载具长、宽、高，或点「标准 / 加宽」预设。
3. 点「点选目标」后在水体任意位置单击选择三维目标，或选用预设目标。
4. 用「剖切轴 / 剖切位置」滑块剖开障碍，勾选「显示配置空间阻挡体素」查看
   按载具体素侵蚀出的不可行空间。
5. 点「运行载具导航」调用后端真实规划；成功后点「▶ 沿路径行驶」，载具按
   实算采样路径运动，左下角实时显示最近障碍距离；失败时红色体素为阻断体积，
   蓝色半透明体素为可达自由分量。

所有路径与阻断体积均由 `/api/plan` 现场计算，界面不存在任何固定轨迹数据。

## 算法与正确性要点

- `src/geometry.js`：有向盒 / 球 / 圆柱的解析 SDF；载具为有尺寸的刚体盒。
  扫掠检定沿运动段密集采样姿态，利用 SDF 的 1-Lipschitz 性质给出
  `实测净空 − 步长/2` 的保守下界，因此只会误拒安全运动，绝不会放行碰撞运动。
  另含朴素中心线检定，用于演示“采样点都为空 ≠ 两点连线安全”。
- `src/grid.js`：轴对齐盒体表面探针侵蚀生成配置空间占据。该侵蚀对任意偏航
  朝向都是必要条件，网格判堵的体素任何朝向都无法容纳载具。
- `src/planner.js`：真三维 26 邻接 A*（含垂直与对角边，代价为欧氏长度）。
  每条边在靠近障碍时再做有向盒扫掠检定，开阔水域用外接球充分条件快速放行；
  偏航离散搜索让载具能转向对齐斜缝。平滑仅删除航点，安全判据不放松。
- `src/engine.js`：独立的高分辨率参考网格（格长为搜索格的一半）做洪水填充，
  独立审计可达性、封闭空腔与净空，并对平滑后的密集采样路径做全程连续复核。

## 三类内置场景

- **沉船外壳**：全宽舱壁只在顶部留缝，入口上方有悬垂顶盖，路线必须先横移、
  再向上翻越、再从交错肋骨间下降——仅垂直绕行可达。
- **斜向狭孔**：30° 斜缝宽度按载具横截面给定；标准载具贴缝通过，加宽载具
  中心线仍在空区但盒体体积无法通过，被扫掠检定拒绝。
- **封闭空腔**：目标位于完全封闭的壳体内，规划器报告不可达并返回壳面阻断
  体积；同场景的外部目标仍可正常规划，证明不是规划器失效。

## 自动化验证

```bash
npm test            # 30 项无头算法断言（场景、体积判定、反例、参考一致性）
node test/ui-test.js  # 需本机 Chromium；驱动真实浏览器点击界面并核对渲染对象
```

`test/selftest.js` 覆盖：垂直绕行确实发生、斜缝体积可通过性、
“中心线为空但扫掠碰撞”的反例、封闭空腔不可达与阻断体积、
规划可达性不超过侵蚀参考网格等。
