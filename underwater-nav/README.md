# 水下载具三维立体导航演示

在沉船外壳、洞穴与悬垂结构之间为**有尺寸的水下运载器**搜索真正的三维路径。
路径不是“水平地图 + 高度标注”，而是在体素配置空间中用 26 邻接 A* 同时搜索
向上、向下与斜向运动；窄缝可通过性按**整个载具盒体**判定，并对平滑后的路线
做连续扫掠碰撞复核。

## 界面怎样启动

前置条件：Node.js 18+（已在 Node 22 上验证），依赖仅 `three`，已随包安装。

```bash
cd underwater-nav
npm install        # 仅首次，安装本地 three.js
npm start          # 等价于 node server.js
```

控制台出现 `Underwater navigation demo: http://localhost:8080` 后，浏览器打开
<http://localhost:8080>。端口可用 `PORT=9000 npm start` 修改。

界面操作顺序：

1. 左侧选择场景（沉船 / 斜向狭孔 / 封闭空腔 / 镜像斜孔）。
2. 调整载具长、宽、高，或点「标准 / 加宽」预设。
3. 点「点选目标」后在水体任意位置单击选择三维目标，或选用预设目标。
4. 用「剖切轴 / 剖切位置」滑块剖开障碍，勾选「显示配置空间阻挡体素」查看
   按载具体素侵蚀出的不可行空间。
5. 点「运行载具导航」调用后端真实规划；成功后点「▶ 沿路径行驶」，载具按
   实算采样路径运动（姿态取**核验过的车道朝向**，而非路径切线），左下角实时
   显示最近障碍距离；失败时红色体素为阻断体积，蓝色半透明体素为可达自由分量。
6. 点「运行诊断探针」沿路径回查：显示出错阶段（栅格化 / 平滑 / 未发现）、网格
   原点平移的可达结论、最早翻转体素、平滑器替换结果与最小复现场景；点「显示
   扫掠体」按各自朝向绘制每个案例的载具扫掠体。

所有路径与阻断体积均由 `/api/plan` 现场计算，界面不存在任何固定轨迹数据。

## 算法与正确性要点

- `src/geometry.js`：有向盒 / 球 / 圆柱的解析 SDF；载具为有尺寸的刚体盒。
  扫掠检定沿运动段密集采样姿态，利用 SDF 的 1-Lipschitz 性质给出
  `实测净空 − 步长/2` 的保守下界，因此只会误拒安全运动，绝不会放行碰撞运动。
  另含朴素中心线检定，用于演示“采样点都为空 ≠ 两点连线安全”。
- `src/grid.js`：**有向盒**配置空间占据。默认模式对每个候选偏航（30° 一档）
  逐一做精确有向盒姿态检定：只要**某个**朝向能容纳载具即判为空闲，并记录该
  空闲朝向 `yawHint`。这正是旧版轴对齐侵蚀出错之处——把盒体转进斜缝只会减小
  缝法向上的投影，轴对齐判定会抹掉载具本可通过的孔。`'axis'` 模式保留为
  **保守上界**（阻挡集为超集，仅用于细粒度参考审计）；`'legacy-axis'` 复现旧
  缺陷，仅供诊断工具对照。
- `src/planner.js`：真三维 26 邻接 A*（含垂直与对角边，代价为欧氏长度），按
  **朝向车道** 求解：载具先原地转到车道朝向，随后以**恒定偏航**平移穿过每一跳
  ——这正是渲染器绘制的姿态。每条边用同一安全裕度做有向盒扫掠检定；首个到达
  目标的车道胜出。平滑仅删除航点，且只接受恒定车道偏航下的安全弦。
- `src/engine.js`：独立的高分辨率参考网格做洪水填充，独立审计可达性、封闭空腔
  与净空；对交付的**每条航段**做连续扫掠复核，并记录密集姿态轨迹与失败时的
  具体碰撞采样（位置、偏航、净空、障碍编号）。只有复核通过才报告成功。

- `src/diagnose.js`：沿路径回查的诊断探针。
  - **探针 A（原点平移）**：固定障碍体积、只平移栅格原点；若可达结论在纯亚格
    原点平移下翻转，则认定为**栅格化**阶段抹去了通道。
  - **探针 B（平滑器替换）**：固定原始 A* 折线、只替换平滑器（车道偏航平滑 vs
    复现旧缺陷的“任一朝向”平滑）；若原始折线在绘制偏航下安全而平滑后不安全，
    则认定为**平滑**阶段把安全折线推进了壳体。
  - **最早翻转体素/线段**：在走廊上按到折线距离排序，找出有向格空闲但轴对齐格
    阻挡的最早体素；在平滑分支上给出最早失安航段。
  - **最小复现关卡**：仅保留最早翻转处的几何与载具体型。
  - 每个结论都附带载具**朝向**与**扫掠体**（按各自朝向的有向盒），不会把两个
    方向不同的案例压缩成同一体素截图。

## 三类内置场景

- **沉船外壳**：全宽舱壁只在顶部留缝，入口上方有悬垂顶盖，路线必须先横移、
  再向上翻越、再从交错肋骨间下降——仅垂直绕行可达。
- **斜向狭孔**：30° 斜缝宽度按载具横截面给定；标准载具贴缝通过，加宽载具
  中心线仍在空区但盒体体积无法通过，被扫掠检定拒绝。
- **封闭空腔**：目标位于完全封闭的壳体内，规划器报告不可达并返回壳面阻断
  体积；同场景的外部目标仍可正常规划，证明不是规划器失效。
- **镜像斜孔**：把 30° 斜缝复制到地图另一方向并再旋转 90°（120°）。缝宽、壁厚
  与载具同场景二，通过性物理相同，但失败朝向不同。起点/目标偏向缝壁，成功
  轨迹紧贴障碍（最小面净空约 0.20 m）却始终合法。两个方向的案例各自保存载具
  朝向与扫掠体，不会被合并成同一张体素截图。

## 自动化验证

```bash
npm test            # 无头算法 + 诊断探针断言（selftest 36 项 + diagtest 27 项）
npm run test:ui     # 需本机 Chromium；驱动真实浏览器点击界面并核对渲染对象
```

`test/selftest.js` 覆盖：垂直绕行确实发生、斜缝体积可通过性（含“轴对齐碰撞、
按缝朝向可通过”的对照）、“中心线为空但扫掠碰撞”的反例、封闭空腔不可达与阻断
体积、有向规划 vs 保守参考的一致性方向（参考可达 ⇒ 规划可达；参考可漏报斜向
通道）。

`test/diagtest.js` 覆盖：平滑器替换把失败归因到平滑阶段且原始折线安全、原点
平移不改变已修正管线的结论、轴对齐栅格误抹的可通行体素与最小复现关卡、失败
标志可追溯到具体碰撞采样、镜像案例的朝向不同且扫掠体保留、以及**过窄洞口不被
同一补丁误放行**（加宽载具无法穿过 2.0 m 斜缝且无假通过）。
